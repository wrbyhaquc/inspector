# Inspector

**看畫面、自動做事。** 接上一個畫面來源 → 教它看懂畫面上的狀態 → 用不用寫程式的腳本自動操作。

[English](README.md) · 繁體中文

**它能做什麼**

- **看任何畫面**:Android 裝置與模擬器(adb)、App 視窗、桌面的一塊區域、RTSP/HTTP 攝影機、影片檔。
- **學會看懂**:你定義重要的狀態(按鈕出現了沒、進度條多滿、一個數字、在哪個區域),回答幾題教它;它自己訓練模型,不用寫程式。
- **用免寫程式的腳本動作**:規則、情境、子腳本、排程、清單與變數;點擊、滑動,或用 HTTP / MQTT / Home Assistant 控制畫面以外的東西。
- **讓人能操作**:手機也能用的簡易操作面板、Discord / Telegram 通知與聊天指令,每個動作都有紀錄。
- **打包成方案包**:把整套設定匯出成有版本的發行版,在別台電腦安裝或升級(Studio 設計、執行版執行)。

**實際看看**:[模擬魚塭](https://github.com/wrbyhaquc/inspector-demo-pond),一台攝影機加四個開關。這段影片裡沒有人動手:晚上魚浮頭,Inspector 打開打氣機;早上白鷺鷥落地,被它趕走。
10 分鐘就能試,不用訓練模型。

![Inspector 照顧模擬魚塭](https://raw.githubusercontent.com/wrbyhaquc/inspector-demo-pond/main/docs/demo.gif)

<img src="https://raw.githubusercontent.com/wrbyhaquc/inspector-demo-pond/main/docs/panel.zh-TW.png" alt="養殖戶用的操作面板" width="640">

平台本身不認得任何一個 App、裝置或場景。要看什麼、怎麼判斷、要做什麼,全部是**專案**的設定;
某個場景需要的特殊能力(專屬的畫面規則、額外的資料來源、別種裝置),由專案的**外掛**提供,再一起打包成**方案包**。

**原則**

- 執行時只看畫面:從畫面來源取得畫面、送出點擊等輸入。不修改或偽造網路封包,不讀寫其他程式的記憶體。
- 新增或調整一個要看的狀態、一個腳本,都在介面上完成,不需要改程式。
- 平台的程式不為單一場景特化;場景專屬的東西放在方案包裡的外掛(`<data>/packs/<代號>/`,每個方案包有自己的 repo)。
- 介面有繁體中文、English、简体中文、日本語、한국어(見 [docs/i18n.zh-TW.md](docs/i18n.zh-TW.md))。

## 系統需求

- 以 **Windows 10 / 11** 為主。視窗擷取、螢幕擷取、送出滑鼠 / 鍵盤(`drivers/window.py`、`desktop.py`、`winput.py`)只支援 Windows;Android 裝置(經 adb)、攝影機 / 串流、錄影檔在其他系統也能用。
- **Python 3.12** 與 **Node.js 20.19 以上**(建置網頁介面一次)。
- Android 裝置:`PATH` 上要有 **adb**(Android platform-tools),或用模擬器自帶的(雷電的會自動找到)。
- 顯示卡可有可無:學習用 NVIDIA 顯示卡(CUDA)快很多;執行用 ONNX,Windows 上任何顯示卡都能經 DirectML 加速,沒有就用 CPU。
- 磁碟:Studio 加 PyTorch 要數 GB;錄製也會占空間(每張畫面是專案大小的 PNG)。

## 安裝與啟動

**Studio**(設計、標註、學習、執行、製作方案包):

```bash
# 先依 https://pytorch.org 裝 torch / torchvision(CUDA 版或 CPU 版)
pip install -r requirements.txt
cd web && npm install && npm run build && cd ..
start.bat                           # 或 python -m server → 打開 http://127.0.0.1:8765
```

**執行版 Runtime**(安裝方案包並執行:監看、操作面板、通知;沒有設計頁面、不能學習、不需要 PyTorch,約 370 MB):

```bash
pip install -r requirements-runtime.txt
cd web && npm install && npm run build && cd ..
start.bat
```

模型以 ONNX 執行,答案和 PyTorch 相同;要學習模型需要 Studio(這台或另一台電腦)。

兩者是同一個程式。有裝 PyTorch 的啟動時是 Studio,沒有的是執行版;也可以在 `inspector.json` 設 `"edition": "studio"` 或 `"runtime"`(或環境變數 `INSPECTOR_EDITION`)明確指定。執行版裡方案包的設計是唯讀的:執行的人改的東西——哪台跑哪個腳本、規則的次數限制、排程時間與參數、清單掃到的名稱、操作面板上的值——都存在執行資料夾,疊在方案包上面,所以安裝新版方案包時全部保留。設計要在 Studio 修改,再以新的發行版安裝過來(見「方案包」)。

**啟動參數**(`python -m server …`):

| 參數 | |
|---|---|
| `--port 8765` | 介面的連接埠 |
| `--no-browser` | 不自動打開瀏覽器 |
| `--lan` | 讓同一個網路的手機、電腦也能連(先設定登入 PIN:「操作面板設計 › 手機連線與登入」) |
| `--start-runner` | 一起啟動腳本執行(照上次啟動的設定) |

`run_service.bat` 讓 Inspector 在背景常駐(重複啟動會被擋下,停掉會自己重開);`restart_inspector.bat` 重新啟動。

**這台電腦的設定**:`%USERPROFILE%\.inspector\` 裡的 `inspector.json`(Windows 以外是 `~/.config/inspector/`;環境變數 `INSPECTOR_CONFIG` 可指定別的檔案)。它永遠不在程式資料夾,所以更新或換掉程式都會保留;舊版放在程式資料夾的會在第一次啟動時自動搬過去。需要時才建:

```json
{"data": "D:\\InspectorData", "work": "E:\\InspectorWork", "language": "zh-TW", "train_cache": "D:\\InspectorCache\\train"}
```

| 欄位 | |
|---|---|
| `data` | 資料根目錄(見下面)。預設是設定旁邊的 `data`,所以新電腦完全不用設定 |
| `work` | 工作資料(錄影、標籤、模型,很大)放哪裡:`<work>/<方案包代號>/`。預設 `<data>/work` |
| `language` | 執行紀錄、通知、聊天 Bot 回覆的語言(也可在「執行 › ⚙ 執行設定」改) |
| `edition` | `studio` 或 `runtime`(見上面);預設:有裝 PyTorch 是 `studio`,沒有是 `runtime` |
| `train_cache` | 學習用的縮小畫面,寫一次、每輪都讀,建議放 SSD。預設 `<data>/runtime/<代號>/train_cache` |
| `project`、`runtime` | 只給舊的單一專案資料夾用(沒有設定 `data` 時) |

環境變數 `INSPECTOR_DATA`、`INSPECTOR_WORK`、`INSPECTOR_PACK`、`INSPECTOR_EDITION`、`INSPECTOR_TRAIN_CACHE` 優先。`python -m project where` 會列出這台電腦的所有位置。

**資料根目錄**:程式資料夾只放程式,每個方案包各自分開;升級平台或抽換方案包都不會動到其他東西:

```
<data>/active.json          {"pack": "<代號>"}:目前執行的方案包
<data>/packs/<代號>/        方案包本身:pack.json、plugin/、design/(project.json + meta/)、models/
<work>/<代號>/              設計時產生的資料:錄影、標籤、測試集、模型、影子紀錄(可放別顆磁碟)
<data>/runtime/<代號>/      只屬於這台電腦:使用者的值、即時狀態、PIN、聊天 Bot、輸出的秘密
<data>/logs/                服務的紀錄檔(run_service.bat)
```

把舊的單一專案資料夾搬過去(原本的只會被讀取;再執行一次會補上之後的變更):

```bat
python -m project.layout migrate --project D:\inspector\myproject --runtime D:\inspector\runtime --data D:\InspectorData --work E:\InspectorWork --link
```

`--link` 讓同一顆磁碟上的圖片與模型檔用硬連結,不另外複製;`--activate` 讓這台電腦改用新結構。把 `"data"` 從 `inspector.json` 拿掉就回到舊的資料夾。

**介面語言**:每個瀏覽器自己選(側邊欄最下面、操作面板右上角)。

## 從空白專案開始

Inspector 不附任何專案或方案包,由你自己建立。新電腦一開始會有一個空的方案包 `default`(`<data>/packs/default/`),它的設計就是你的專案。「首頁:下一步」永遠會告訴你下一步做什麼;完整走一遍是這樣:

1. **來源**:「+ 加入來源」,掃描這台電腦(模擬器、手機、視窗、螢幕、攝影機、錄影檔),勾選要用的。確認畫面大小和專案的座標空間相符(`project.json` 的 `screen`,預設 1280×720);比例不同時頁面上會提醒。
2. **要看的狀態**:「+ 新增狀態」,先做一個要認的東西,例如「看不看得到開始按鈕」(分類:是 / 否)。在範例畫面上框出範圍,選一種畫面規則(參考圖比對最簡單:每個答案挑幾張畫面)。
3. **錄製**:錄一段,把你在意的畫面都走過(每個狀態的每種答案都要出現)。
4. **自動標註**:「產生標籤」(預設錄完會自動做)。
5. **回答問題**:每個狀態回答約 20~30 題考題(每種答案至少 3 題)。考題只用來打分數。
6. **學習**:開始學習(Studio)。狀態通過考試前,腳本會先用畫面規則判斷,所以可以先往下做。
7. **腳本**:建一個主腳本、一條規則:*如果* 看得到開始按鈕,*就* 點它。要點的按鈕在「素材庫 › 按鈕」取名字。
8. **執行**:「啟動執行程式」。新腳本和新來源一律從**試跑**開始:看時間軸,確認它*會*做什麼。
9. 看起來正確,再到「執行 › 部署」改成**正式執行**。隨時可以每台或全部 停下來 / 暫停 / 繼續。
10. 其他:給使用者的**操作面板**、**排程**、**通知**與聊天指令、**腳本測試**。

要交給另一台電腦,就匯出成方案包,再到那台安裝(見「方案包」;頁面在「④ 交付」)。

選單照使用的順序分成三段:

| 區塊 | 頁面 | 做什麼 |
|---|---|---|
| | **首頁:下一步** | 平台整理出現在該做的事(考題不夠、有新畫面還沒學、腳本存下拿不準的畫面…),點按鈕直接過去 |
| ① 要看什麼 | **要看的狀態** | 要看畫面上的哪些狀態、看哪個範圍、有哪些答案;每個狀態的學習進度 |
| | **來源**、**錄製** | 選畫面來源;開始 / 停止錄製(收集器) |
| ② 教它看懂 | **回答問題** | 人工回答考題;只問某一題、補考題、回答執行時存下的畫面;替名稱庫命名 |
| | **學習** | 訓練模型 |
| | **成績與錯題** | 每次學習的考試成績、答錯的畫面 |
| ③ 自動化 | **腳本**、**腳本測試**、**排程**、**素材庫** | 守門規則、主腳本、子腳本、變數、按鈕、清單、範本、輸出、使用者設定、重播 |
| | **執行** | 啟動執行程式;部署腳本到各台;停下來 / 暫停 / 繼續;每台的即時狀態與時間軸 |
| | **操作面板設計**、**操作面板** | 給使用者的簡化頁面(設定、排程、按鈕),也能從聊天 Bot 使用 |
| ④ 交付 | **方案包** | 已安裝的方案包與執行中的是哪一個;安裝或升級發行版、切換、重新啟動 |
| 進階工具(預設收起) | **畫面瀏覽**、**自動標註** | 檢查內部細節 |

執行版只顯示**首頁**、**執行**、**來源**、**操作面板**、**方案包**。

## 檔案放在哪裡

專案就是方案包的設計。`<data>`、`<work>` 與設定檔在「安裝與啟動」說明;`python -m project where` 會列出這台電腦的實際位置。

| 位置 | 內容 |
|---|---|
| `%USERPROFILE%\.inspector\inspector.json` | 這台電腦的設定:資料根目錄在哪裡、用什麼語言、哪個版本 |
| `<data>/active.json` | 目前執行的方案包 |
| `<data>/packs/<代號>/pack.json` | 方案包是什麼、需要什麼(見「方案包」) |
| `<data>/packs/<代號>/plugin/` | 方案包的外掛(見「外掛」) |
| `<data>/packs/<代號>/design/project.json` | 專案名稱、座標空間(`screen`)、預設 App、用語(`words`,例如裝置叫什麼)、裝置來源(`devices`)、要載入的外掛(`plugins`) |
| `<data>/packs/<代號>/design/meta/` | 所有設計:`states/`(狀態定義)、`rule_templates/`(參考圖)、`scripts/`、`subscripts/`、`variables.json`、`buttons.json` 與 `buttons/`、`lists.json`、`schedules.json`、`panel.json`、`user_settings.json`、`templates.json`、`tests.json`、名稱庫 |
| `<work>/<代號>/sessions/`、`labels/`、`testset/`、`models/`、`shadow/` | 錄製的資料、自動標註、測試集、訓練好的模型、腳本執行留下的紀錄(紀錄、稽核畫面、拿不準的畫面) |
| `<data>/runtime/<代號>/` | 只屬於這台電腦:使用者的值、覆寫與清單名稱、即時狀態、PIN、聊天 Bot、輸出的秘密;`runtime.json` 是它的格式版本(舊的會先備份到 `.backup/` 再自動升級) |
| `<data>/logs/` | 服務的紀錄檔 |

設定都有版本或只新增,改壞了可以還原。以上都不在程式資料夾裡。

## 外掛

外掛是方案包 `plugin/` 資料夾裡的 Python 套件,`plugin.py` 定義 `register(reg)`;`pack.json` 的 `"plugin"` 指名它,載入時的名稱是 `packs.<名稱>`。專案在 `project.json` 的 `plugins` 列出要載入哪些。外掛點(`project/plugins.py`):

| 種類 | 用途 |
|---|---|
| `rule` | 畫面規則的種類(一次回答一個或多個狀態;`labeler/rules.py` 說明介面) |
| `label_source` | 自動標註時除了畫面規則以外的答案來源(例如場景自己的資料;`labeler/build.py`) |
| `recorder` | 收集時除了截圖以外另外記錄的資料(`collector/collector.py`) |
| `source` | 裝置來源:畫面從哪裡來、動作送到哪裡(`drivers/__init__.py`) |
| `gallery_cut` | 名稱庫切出名稱的方式(`labeler/gallery.py`) |
| `notify` | 通知管道(內建 Discord 等,`notify/channels.py`) |
| `api` | 外掛自己的網頁 API,掛在 `/api/plugins/<名稱>/` |

外掛載入失敗(或方案包需要較新的 Inspector)不會讓平台停擺,「首頁:下一步」會說明原因。

## 方案包

方案包 = 一個外掛 + 一份專案設計(狀態、參考圖、按鈕、清單、腳本、排程、面板…),可以再帶一個訓練好的模型(只放 ONNX 與考試報告);不含錄製資料。
方案包由使用 Inspector 的人自己製作、自行部署或發佈;這個 repo 不含任何方案包。

開發中的方案包就是資料目錄結構裡的一個資料夾 `<data>/packs/<代號>/`(`pack.json`、`plugin/`、`design/`),建議它本身就是一個 git repo:錄影、標籤、模型、使用者的值和秘密都在它外面(`work/` 與 `runtime/`),所以 git 看到的只有方案包的原始碼。要交給別人的是**發行版**:匯出會把方案包做成一個 zip,不含歷史、備份、紀錄檔和舊版腳本。安裝較新的發行版會原地升級,執行的人改過的值都會保留。

> 秘密只留在這台電腦:登入 PIN(`<data>/runtime/<代號>/access.json`)、聊天 Bot(`<data>/runtime/<代號>/notify.json`)、輸出的秘密欄位(HTTP 標頭、MQTT 密碼、Home Assistant 權杖,存在 `<data>/runtime/<代號>/output_secrets.json`)都不會被匯出。輸出的其他設定(網址、主機、主題)屬於設計,會跟著方案包走:交給別人之前請檢查一下。

```bash
python -m project.pack export [--version 1.2.0] [--model latest] [--out <資料夾>]   # 目前的方案包 -> <代號>-<版本>.zip(預設放在 <data>/releases)
python -m project.pack install <zip 或資料夾> [--activate]                          # 安裝,或升級成較新的版本
python -m project.pack list                                                          # 已安裝的方案包(● = 使用中)
python -m project.pack use <代號>                                                    # 改用另一個已安裝的方案包
```

`install` 會把方案包放到 `<data>/packs/<代號>/`。已經有的只會被較新的版本取代(舊版留在 `<data>/packs/.previous/`);開發中的方案包(git 工作資料夾)不會被蓋過。安裝或切換使用中的方案包之後,請重新啟動 Inspector。單一專案資料夾時,用 `export --plugin <名稱>` 把專案和那個外掛做成發行版。

每個方案包都有一個 `pack.json`,說明它是什麼、需要什麼(`project/manifest.py`):

```json
{"format": 1, "id": "my_pack", "name": "我的方案包", "description": "", "version": "1.2.0",
 "plugin": "my_plugin", "requires": {"platform": ">=0.1.0", "spec": 8},
 "requirements": "plugin/requirements.txt", "model": null}
```

| 欄位 | |
|---|---|
| `format` | pack.json 本身的格式版本(1) |
| `id` | 小寫英文、數字、`_`、`-`;也是 `<data>/packs/` 底下的資料夾名稱 |
| `version` | 方案包自己的版本,`主.次.修` |
| `plugin` | `plugin/` 裡的外掛(Python 套件名稱);只有設計時為 `null` |
| `requires.platform` | 可以執行它的 Inspector 版本,例如 `>=0.1.0, <1` |
| `requires.spec` | 設計使用的腳本規範版本(`automation/spec.py`) |
| `renamed` | 這一版比上一版改了哪些代號,例如 `{"schedules": {"舊": "新"}, "rules": {"<腳本>/舊": "新"}}`(種類:scripts、situations、rules、schedules、settings、lists、vars)。安裝在舊版上時,執行端為舊代號設定過的值會一起搬過去;對不到任何項目的值會列在「方案包」頁與「下一步」 |
| `author`、`license`、`homepage` | 選填 |

需要較新 Inspector 或較新腳本規範的方案包不會被載入,「首頁:下一步」會說明原因。也可以手動檢查或升級:

```bash
python -m project.manifest check <方案包資料夾>
python -m project.manifest upgrade <方案包資料夾>
```

# ① 要看什麼

## 要看的狀態(狀態定義)

模型要辨識哪些狀態、每個狀態看畫面的哪個範圍、有哪些答案,集中定義在一份有版本的設定(`meta/states/v<N>.json`)。
自動標註、回答問題的題目與快速鍵、畫面瀏覽、腳本的條件,全部依照這份定義。

| 類型 | 用途 |
|---|---|
| 分類 | 固定的幾個答案,例如 開 / 關 / 看不到 |
| 比例 0~1 | 例如會填滿的長條 |
| 數值 | 畫面上讀到的數字 |
| 名稱庫 | 畫面上的一段文字或圖示,人工命名一次後自動認出(`labeler/gallery.py`) |

**新增狀態不用寫程式**:標籤來源選「畫面規則」,再選規則種類(`labeler/generic.py`),或選外掛提供的規則:

| 規則 | 怎麼判斷 | 怎麼設定 |
|---|---|---|
| 參考圖比對 | 每個答案存幾張參考圖,和畫面比相似度;最像、超過最低相似度、且領先第二名的答案勝出;都不像時用「都不像時」的答案 | 從畫面點一張、選答案加入 |
| 顏色比例 | 範圍內符合某些 HSV 顏色的像素比例,高於 / 低於門檻各代表一個答案 | 在放大圖上點顏色、看比例分布設門檻 |
| 長條比例 | 長條填滿了多少,換顏色也量得到 | 框住長條、選填滿方向 |
| 讀數字 | 範圍內的數字 | 點數字的顏色,每個字元教幾次 |

- 可以指定「先決條件」:另一個狀態看不到時,這個也算看不到。
- 模型還沒學過的狀態,執行腳本時直接用規則判斷,所以新狀態馬上能用;下次學習時會一起學。
- **學習進度**:每個狀態顯示四步:定義好 → 能判斷 → 有考題 → 模型學會,並標出下一步要做什麼。

## 來源與錄製

**來源**(`drivers/`)決定畫面從哪裡來(眼)、動作送到哪裡(手)。來源分大類,每類有幾個常用產品的預設(只是建議值,每項都能改),每種來源宣告自己能做什麼(取得畫面、點擊、長按、滑動、返回鍵、啟動 App、偵測有人操作):

| 大類 | 說明 |
|---|---|
| Android(`android/`) | adb 連得到的任何裝置;預設:雷電、MuMu、BlueStacks、夜神、逍遙、實體手機。可擷取模擬器視窗(不拖慢)、adb 送出輸入、`getevent` 偵測真人操作 |
| 應用程式視窗(`window.py`) | 任何程式的視窗(NVR 用戶端、瀏覽器、辦公軟體…);滑鼠 / 鍵盤送到視窗 |
| 螢幕區域(`desktop.py`) | 某個螢幕或其中一塊 |
| 串流(`stream.py`) | RTSP / HTTP 攝影機、網路串流;只看不動手(動作可以交給別的來源或輸出) |
| 錄影檔(`video.py`) | 資料夾裡每個錄影檔是一個來源,即時播放、播完重頭;只能取得畫面 |
| 外掛提供的 | 專案的外掛可以再加 |

腳本用到來源做不到的動作時,儲存腳本會被擋下。

**收集器**錄下每台的畫面與觸控(外掛可以另外記錄別的資料);**收集器不會點擊或送出任何東西。**

```bash
python -m collector                 # 錄到按 Ctrl+C 為止(平常從介面啟動)
python -m collector --minutes 60 --interval 5 --only <裝置名稱>
```

- **取樣**:每台每 N 秒一張(`base`);最近有觸控時每秒一張(`active`);觸控前最後一張(`pre_touch`,從記憶體緩衝取);外掛回報的事件後 0.3 / 0.8 / 1.5 秒。
- 資料結構:

```
<work>/<代號>/sessions/<YYYYMMDD_HHMMSS>/
  session.json
  devices/<裝置>/
    samples.jsonl                 每次取樣:時間、觸發原因、外掛記錄的狀態
    events.jsonl / touches.jsonl  事件、觸控手勢(含 pre_frame)
    frames/<id>.png               完整畫面(專案的座標空間)
```

腳本執行時存下的畫面(「判斷錯了」、拿不準的畫面)放在場次 `shadow_<日期>`,格式相同。

# ② 教它看懂

## 自動標註(labeler)

把每張畫面依狀態定義產生標籤(弱監督),學習時用:先跑畫面規則(外掛的、通用的),再交給外掛的標註來源補上或修正,最後是名稱庫。

```bash
python -m labeler [--session <場次>]
```

輸出 `<work>/<代號>/labels/v<版本>/labels.jsonl`(每張一行)、`summary.json`、`review_candidates.jsonl`(考題候選)、`rule_cache.jsonl`(規則快取,只算新畫面)。
規則沒把握時該標籤留空並加旗標(例如 `<狀態>_uncertain`),學習時跳過,或依規則的設定當成「看不到」。

## 回答問題(測試集)

人工回答的答案是**考題**,用來替模型打分數,不拿來學。

- 存在 `<work>/<代號>/testset/testset.jsonl`(只新增,同一張以最後一次為準)。每筆記 `reviewer`:`human` 或 `claude`(預標);預標不會蓋掉人的答案。
- 考題候選固定在 `testset/candidates.json`,規則改了也不會換題,不同版本的成績才能比較。
- **只問一題**、**補 30 題**、回答**執行時存下的**畫面(回答後每 4 張有 3 張當學習資料,1 張當考題)。
- 名稱庫的狀態各有一個分頁:相同的名稱已自動分群,每群命名一次。

## 學習(trainer)

```bash
python -m trainer --config-json "{\"epochs\": 20, \"pretrained\": true}"
```

- **模型**:ResNet18 主幹看整張畫面,每個狀態一個小頭;頭保留空間位置,所以會自己學「看哪裡」。
- **資料切分**:考題完全不拿來學;可勾選「保留裝置」(模型完全沒看過的裝置)用來挑最好的一輪;考題前後的畫面排除;其餘有標籤的畫面拿來學。
- 學習前標籤過期會自動重新產生(有新錄製、狀態定義、參考圖、名稱庫或外掛改過)。
- 輸出 `<work>/<代號>/models/<訓練編號>/`:`config.json`、`metrics.jsonl`、`model_best.pt`、`eval.json`(考試報告、混淆矩陣、答錯清單),以及給執行端用的 `model.onnx` + `model.json`(自動轉出,會檢查和 PyTorch 的答案一致)。舊的訓練結果用 `python -m trainer.onnx_export --all` 補轉。

## 成績與錯題

- 每個狀態一張成績卡:答對率、沒看過的裝置的答對率、同一批題目上畫面規則的成績。
- **通過考試**(`runtime/judge.py`):至少 20 題考題、每種答案至少 3 題、不比畫面規則差、沒看過的裝置至少答對 90%。
- **執行腳本時誰來判斷**:模型通過的狀態用模型;模型沒學過或沒通過、而且有畫面規則的,用畫面規則。模型沒把握時由畫面規則幫忙確認(每個狀態可設 自動 / 只用模型 / 只用規則)。

# ③ 自動化

## 腳本的組成

| 組件 | 說明 |
|---|---|
| **🛡 全域守門規則** | 每台裝置、每個主腳本之前**最先**檢查。「停下這台」停掉這台所有腳本;「暫停其他腳本」條件成立期間其他腳本都不動作 |
| **主腳本** | 常駐執行,有**優先順序**,由一或多個**情境**組成 |
| **情境** | 每台裝置同一時間只在主腳本的一個情境裡,只檢查那個情境的規則;可設「進入時先做的事」和「最長停留」 |
| **規則** | 「如果…就…/否則如果/否則」,由上往下檢查,第一條符合的執行;可設冷卻、每小時 / 每天上限、**緊急** |
| **子腳本** | 多步驟的動作,像函式一樣被呼叫:參數、成功 / 失敗、收尾步驟、總時間上限 |
| **變數** | 計數器或「上次的時間」。每台各自一份或全部共用;每天 0 點歸零或不歸零 |
| **按鈕庫** | 取好名字的點擊位置;勾「找圖」的按鈕會先在畫面上找它的圖片再點 |
| **清單** | 一串可選的項目(每台各自或共用),可以從畫面上擷取;腳本參數、設定、面板都能從清單選 |
| **範本** | 「+ 從範本新增」:平台通用的範本,加上專案自己的範本(`meta/templates.json`) |
| **輸出** | HTTP / Webhook、MQTT、Home Assistant:腳本的「送到輸出」可以控制畫面以外的設備 |
| **使用者設定** | 使用者在操作面板上選的值,腳本執行時讀取 |
| **排程** | 每天定時在指定的裝置上執行一個子腳本,每台每天一次,可設補做時間與時間上限 |

### 條件的種類(`automation/conds.py`)

狀態、剛變成、一段時間內幾次、變化量、時段、總是(搭配冷卻)、變數、距離上次、其他裝置的狀態、畫面上看得到按鈕、比較兩個數字。
模型對條件需要的狀態沒把握時,腳本停在那條規則等待,不會跳去執行後面的規則。

### 動作與子腳本步驟

點擊、長按、滑動、返回鍵、輸入文字、啟動 App、在清單中找到並點擊、擷取清單、等待秒數、等到條件成立、如果…否則、失敗就重試、重複直到、清單裡每一個都做、呼叫子腳本、設定變數、通知、問使用者(附按鈕,聊天裡也能回答)、送到輸出、結束(成功 / 失敗)、停下這台、原地等著、暫停其他腳本(限全域守門規則)、切換情境(限主腳本)。

## 執行與監看(runtime)

```bash
python -m runtime [--run <訓練編號>] [--interval 1]     # 平常從介面「啟動執行程式」
```

- 模型:訓練結果有 `model.onnx` 就用 ONNX(不需要 PyTorch),沒有才用 `model_best.pt`;「執行」頁會顯示用的是哪一種。
- 每一輪:取得每台畫面 → 模型一次判斷全部 → 平滑 → 畫面規則補上模型不負責的狀態 → 每個腳本依各台目前的情境決定 → 同一決定連續 2 次才算數(緊急規則除外)。設計一儲存就自動重新載入。
- **每台各自獨立**:每台有自己的情境、子腳本進度、計時、冷卻、變數與指令通道。
- **模式**:每個腳本、每台裝置設定 關閉 / 試跑(只看不點)/ 正式執行(「執行 › 部署」)。
- **安全機制**:每台或全部 停下來 / 暫停 / 繼續(「執行」頁、操作面板或聊天);偵測到有人操作時那台暫停;啟動確認;點擊上限、冷卻、規則沒效果就暫停並通知;每次真的輸入都留紀錄與畫面。
- **持續改進**:模型拿不準、或模型和畫面規則判斷不同時,自動存下畫面到「回答問題 › 執行時存下的」。

## 通知與聊天指令(`notify/`)

通知管道有 Discord Webhook、Telegram Bot、Discord Bot。Bot 除了送通知,也能在聊天裡下指令;Inspector 主動連出去,不用開連線埠或架伺服器。

- 設定:Telegram 向 @BotFather 拿 Token;Discord 在開發者網站建 Bot、打開 Message Content Intent,再用頁面上的連結邀請進伺服器。
- 配對:按「配對」顯示 6 位數配對碼(10 分鐘有效),在要收通知的對話傳給 Bot;只有配對過的人下的指令才會執行。
- 指令:`選單` · `狀態` · `畫面 <裝置>` · `停下來` / `暫停` / `繼續 [裝置|#標籤|全部]`(裝置名稱可以只打一部分;英文、簡體也認得),加上操作面板開放的項目。改設定和按按鈕都會先問確認。
- 每個指令都記在 `<data>/runtime/<代號>/commands.jsonl`。

## 重播(runtime/replay.py)

選一段錄影,讓腳本(可以用還沒儲存的版本)跑一遍,看它在每個時刻會怎麼判斷、切換到哪個情境、會點哪裡。不會碰到任何裝置。

## 腳本規範(automation/spec.py)

腳本、子腳本、變數、輸出、操作面板、腳本測試的檔案格式有版本(目前第 8 版)。
JSON Schema 在 `docs/spec/v<N>/`(由 `python -m automation.spec_schema --write docs/spec/v<N>` 產生),網頁也可以從 `/api/spec/schema/<script|sub|variables|outputs|panel|tests>` 取得。

- 每份檔案記錄 `"format"`;舊檔讀進來自動升級,比這個 Inspector 新的版本會被拒絕讀取。
- 數字與文字欄位可以填值本身,或 `{"param": …}` / `{"setting": …}` / `{"var": …}`(執行時取值);文字可用 `{代號}` 帶入目前的值。
- 已發布版本的欄位不會改名、刪除或改變意思;要新增種類或欄位就升版本並附上升級。
- 主腳本、子腳本的編輯畫面有「JSON」分頁:直接看、改、貼上,按「套用」前會先用 Schema 檢查。

## 分享子腳本(automation/share.py)

「素材庫 › 分享子腳本」:勾選子腳本(可連同它呼叫的子腳本)產生分享檔,下載或複製文字給別人。分享檔包含子腳本本身、用到的按鈕(含找圖的圖片),以及用到的狀態、變數、使用者設定、清單與輸出的名稱;輸出的網址不會放進去。

匯入時先「讀取」,列出每個參照在這裡對應到什麼(先比代號、再比名稱):按鈕可以對應到自己的,或用對方的建立新的;狀態、清單、輸出要對應到這裡已有的;缺的變數和使用者設定自動新增。子腳本代號撞到時可以覆蓋(存成新版本)、另存新代號或不匯入。匯入前全部都要通過腳本規範檢查,任何一個不通過就什麼都不存。

## 腳本測試(runtime/replaytest.py)

把一段錄影加上「預期結果」存成測試(像單元測試),改了腳本、狀態定義或模型之後按「全部執行」,就知道有沒有改壞。

- 預期結果:結束時在某個情境 / 會(不會)進入某個情境、會(不會)呼叫某個子腳本、會(不會)點擊(可指定規則)、會(不會)停止、會(不會)出現警示;可加次數與「只看第幾秒到第幾秒」。
- 不用自己寫:重播看過覺得正確,按「存成測試」,這次的行為就變成預期結果,再到「腳本測試」頁修改。
- 用已儲存的腳本和最新的模型重播;子腳本不實際執行,結果用假設的(可以每個子腳本分別指定)。
- 測試存在 `meta/tests.json`(跟著方案包走);結果在 `<data>/runtime/<代號>/tests/results.json`,沒通過的會出現在首頁「下一步」。

```bash
python -m runtime.replaytest [--id <測試代號>]     # 全部通過時結束代碼 0
```

## 已知限制

- 子腳本只在正式執行時真的執行;重播與試跑都不會真的跑子腳本。

## 常見問題

| 看到的狀況 | 怎麼辦 |
|---|---|
| 「Inspector 已經在執行(連接埠 … 已被使用)」 | 已經有一個 Inspector(或別的程式)占用連接埠:用正在跑的那個、執行 `restart_inspector.bat`,或用 `--port` 換一個 |
| 剛啟動時頁面一直「讀取中」 | 啟動後第一次整理「下一步」會把資料全讀一遍,可能要一分鐘;之後就快了 |
| 視窗來源沒有畫面 | 視窗被縮到最小或關掉了,把它打開;標題改了的話到「來源」頁接回 |
| 找不到 Android 裝置 | 在命令列執行 `adb devices` 確認;安裝 Android platform-tools,或在來源的進階設定指定模擬器的 adb |
| 點擊位置跑掉 | 畫面比例和專案的座標空間不同,「來源」頁會說要改什麼 |
| 執行時某個狀態常常沒把握 | 回答「回答問題 › 執行時存下的」畫面,再重新學習(「學習」頁會告訴你什麼時候值得學) |

## 安全與使用責任

- 預設只有這台電腦能打開介面。`--lan` 會開放給同一個區域網路:請先設定使用者與顧問的 PIN。不要把連接埠開放到網際網路。
- 錄影、模型與設定都留在這台電腦;除了你自己設定的通知和輸出,不會送出任何東西。
- 你輸入的秘密(PIN、Bot 權杖、輸出的密碼、權杖與標頭)存在執行資料夾(`<data>/runtime/<代號>/`),不在設計裡,匯出方案包也不會帶走。輸出的網址與主機屬於設計;分享任何東西時請不要附上執行資料夾。
- Inspector 只透過畫面和一般的輸入操作其他軟體。自動操作某個 App 或服務仍可能違反它的使用條款;怎麼用、用在哪裡由你自己負責。
